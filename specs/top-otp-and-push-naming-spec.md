# 契约规范：顶栏验证码磁贴与推送状态二元对账规范 (AIR-49)

## 1. 顶栏推送状态与二元外推契约
系统消息与控制台正名后，废止所有“本地宽带代推”、“免流量保护”、“端口 17800”等技术装腔用词，严格遵循如下二元对账契约：

| 场景 | 上位机在线模式 (PC-First) | 板端脱机自发模式 (Standalone Cellular) |
|---|---|---|
| **执行实体** | Windows 宿主 `gateway_hub.py` | 蜂窝模组固件 `notify_service.lua` |
| **信道途径** | 宿主机网络通道 | 模组 4G 基带 SIM 卡蜂窝数据流量 |
| **Web 顶栏状态** | `● 上位机推送`（正常在线状态，绿灯） | （脱机时 Web 控制台标 `● 服务离线`） |
| **飞书/钉钉/企微底栏** | `来源: {设备型号} · IMEI {imei} (上位机推送)` | `设备: {dev_label} （4G蜂窝直推）` |
| **单卡/多卡对账** | 集群模式标出 `[{slot_id}]`，如 `[SLOT_1] Air780E (上位机推送)` | 单板输出 `Air780EPV （4G蜂窝直推）` |

## 2. 顶栏极简验证码磁贴 (Micro OTP Capsule) 规范
为满足用户“固定依赖路径 / Muscle Memory”的核心诉求，顶栏居中提供永久定址的验证码磁贴：

### 2.1 表现与尺寸
- **常态尺寸**：高度 24px，宽度自适应收敛在 110px ~ 130px，不霸占顶栏空间；
- **排版结构**：`🔑 [验证码] [时间标记]`；
- **多卡集群兼容**：卡槽与号码信息不侵占按钮正文空间，完整折叠在容器的 Hover Title 中：
  `title="来自卡 2 (联通 3879) · 2分钟前接收 · 点击复制"`。

### 2.2 三级新鲜度生命周期
1. **鲜活期 (`< 5m`)**：
   - 样式：金色边框 `rgba(245, 158, 11, 0.35)`，金色文字 `#fbbf24`，100% 不透明度；
   - 时间：`刚刚` 或 `Xm`。
2. **温和期 (`5m ~ 15m`)**：
   - 样式：边框微弱淡化，75% 不透明度；
   - 时间：`Xm`。
3. **沉淀期 (`> 15m`)**：
   - 样式：添加 `.stale` 类，45% 半透明暗灰金，去饱和度；
   - 悬停提示：明确标注 `(历史验证码 · 超过15分钟)`；
   - 仍支持点击复制，满足回顾历史验证码的低频长尾诉求。
4. **空状态**：
   - 本地未曾收到任何验证码时，容器彻底隐藏（`display: none`），顶栏保持通透留白。

### 2.3 原地点击反馈 (In-Place Feedback)
- 用户点击后，原位 800ms 轻量切换为 `✓ 已复制`，边框呈现绿色微光，0.8 秒后平滑回弹复原，不触发突兀的弹窗或打断操作。
