# 合宙 780 系列模组烧录、避坑与救砖指南

本文档沉淀合宙 4G 模组在固件烧录、底层避坑、强刷救砖与通电自启改线中的核心硬核技术事实。

---

## 一、 推荐刷机工具链

1. **第一梯队（上位机内置线刷·推荐）**：  
   网关上位机已内置移芯原厂无头线刷引擎（基于 `tools/flasher/FlashToolCLI.exe`）。插上模组后，可在 Web 控制台一键全量刷机（约 10 秒）或极速更新脚本（约 2 秒），无需安装任何第三方工具。
2. **第二梯队（合宙官方 Luatools）**：  
   官方成熟可视化工具。在【项目管理测试】中导入工程或添加脚本，勾选底层后烧录。
   * **编码避坑警告**：如果通过脚本自动生成或修改 Luatools 项目 `.ini` 文件，**编码必须保存为 Windows 原生 ANSI (GB18030 / CP936)**。若存为无 BOM 的 UTF-8 格式，Luatools 解析中文字符路径时会报错 `底层core文件不存在!!` 并导致烧录失败。

## 二、 固件避坑实录：103 vs 109 崩溃死锁真相

在 Air780EPM（移芯二代平台）中，合宙官方发布了多个不同尾号的 `V2050` 底层固件。这是原厂根据不同用途进行的编译期裁剪：

| 固件包文件名 | 固件尾号 | 脚本空间 | 是否含 `sms` 库 | 官方定位与适用场景 |
| :--- | :---: | :---: | :---: | :--- |
| **`LuatOS-SoC_V2050_Air780EPM_103.soc`** | **`103`** | **448 KB** | **✅ 完整保留** | **【标准全能版·本项目唯一指定】** 预留最大脚本空间，保留完整短信与通信外设库。 |
| **`LuatOS-SoC_V2050_Air780EPM_109.soc`** | **`109`** | **288 KB** | **❌ 彻底移除** | **【随身 WiFi 网卡版】** 专用于纯 4G 上网卡。为了塞入网卡驱动协议栈，原厂把 `sms` 库直接删掉了。 |

### ⚠️ 错刷 109 固件的典型崩溃调用栈
如果给 780EPM 刷了 109 固件，不插卡时看似正常；一旦插入手机 SIM 卡，模组入网瞬间触发短信服务，就会直接崩溃：
```text
E/main sms_service.lua:110: attempt to index a nil value (global 'sms')
E/main Lua VM exit!! reboot in 15000ms
```
**现象**：由于缺少 `sms` 库导致虚拟机报错退出，硬件看门狗反复复位重启，电脑 USB 频繁断开重连并弹出 `[WinError 22] 设备不识别此命令`，陷入无限死锁。**若遇到此现象，请立即使用下方 S1 强刷步骤重新灌入 `103` 固件**。

## 三、 S1 按键出厂 BootROM 强刷救砖

移芯芯片内部光刻了不可抹除的硬件 BootROM。无论固件损坏、写错死循环还是开机死锁，均可 100% 物理救活：

1. 拔掉模组的 Type-C 数据线；
2. **用手按住板子上的 `S1`（BOOT）按键不松开**；
3. 将 Type-C 线重新插回电脑 USB 口；
4. 此时芯片强制切入底层下载态（设备管理器显示为专有下载端口，硬件 ID 为 `17D1:0001`）；
5. 松开 `S1` 按键，打开 Luatools 或上位机刷机工具，重新选择正确的标准底包（如 `V2050_103.soc`）烧录，模组即可彻底满血复活。

## 四、 S2 按键 / R6 焊盘通电自启改线（附安全依据）

老款开发板（如 `EVB_Air780X_V1.5` / EC618）插入 USB 后默认是关机状态，每次都要长按开机键才通电。

* **安全改线原理**：  
  芯片引脚 7（`POWKEY` 开机脚）内部自带弱上拉，且板载回路上串联了 **5.6kΩ 限流保护电阻**。外部将开机脚直接短接到地属于官方认证的安全操作，绝不会烧毁引脚或芯片。
* **自启动改装方法**：
  * **简易法**：用一小截细导线或焊锡将 `S2`（POW 按键）的两个对角引脚直接短接；
  * **规范法**：用电烙铁在板子背面的 `R6` 贴片焊盘上补上一坨焊锡短接。
* 改装后插上充电头或电脑就能自动开机入网，免去人工按键看护。

## 五、 FOTA 空中固件更新

网关已内置 FOTA/SOTA 更新协议。设备长期通电运行时，可通过下发空中更新指令让模组自动从服务器拉取 `script.bin` 写入升级分区并重启（耗时约 3 秒，不丢已存短信）。具体协议设计详见系统架构手册。

## 六、 全量安全线刷与三大芯片内存映射 (AIR-44 规范)

### 1. 工业级安全去毒化原则（零全片抹除）
- **绝不全片擦除**：彻底弃用 `format.json` 与 `erallum 0x0`，全量安装严禁盲抹 Flash 起始地址；
- **安全分卷写入**：严格执行 `burnbatch --imglist bootloader system cp_system flexfile2`，仅覆写引导加载器、AP 系统、通信基带与网关脚本；
- **核心出厂资产完整保全**：完好保护机身 IMEI、SN、出厂 NV 及射频校准表（RF Calibration Table），杜绝刷机后无信号或频偏变砖。

### 2. 三大芯片分区基地址矩阵 (Memory Map)

| 芯片架构 / 硬件型号 | Bootloader 基地址 | AP 系统基地址 | CP 通信基带基地址 | 脚本 (LuaDB) 基地址 | 射频校准保留区 | ROM Version 握手标识 |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **EC718PV**<br>(Air780EPV / EP) | `0x3000` | `0x7c000` | `0x18000` | `0x324000` | `0x3f2000` (4KB) | `0000000103040000` |
| **EC718PM**<br>(Air780EPM) | `0x3000` | `0x82000` | `0x1e000` | `0x279000` | `0x3f2000` (4KB) | `0000000103030000` |
| **EC618**<br>(Air780E / EC / 700E) | **`0x4000`**<br>(严禁 0x0) | `0x24000` | **省略 burnaddr**<br>(原厂缺省) | `0x24D000` | `0xe7000 / 0xce000` | `0000000302000000` |

> ⚠️ **EC618 关键安全红线**：
> 1. EC618 的 Bootloader 烧录基地址必须严格设为 `0x4000`。若错误写入 `0x0` 会覆写 Flash Header 导致模组彻底无法引导；
> 2. `[cp_system]` 配置项必须完全省略 `burnaddr` 行以使用芯片缺省，严禁输出空串或 `0x0`。

### 3. 全新裸板 Hub 维护锁与 120 秒 TTL 自愈机制
- **租约加锁与正常释放**：对无 slot 的全新裸板以物理拓扑主键 `unassigned_{port}` 建立维护租约，烧录成功后立即显式解锁；
- **120 秒超时 TTL**：防止烧录中途拔线导致永久 `409 BUSY` 挂死，超期自动重置；
- **S1 硬件救砖通道**：断电或异常断开后，芯片光刻 BootROM 永不损坏，按住 S1(BOOT) 插线即可唤醒下载口 (`17D1:0001`) 重新点按重试刷机。

## 七、 EC618 射频校准表丢失、数据结构解剖与微创恢复指南

### 1. 故障机理与病因复盘
在移芯 EC618（Air780E / Air780EC / Air700E）架构中，`cp_flash` 基地址为 `0x8800000`，其 Flash 中存在两个极其关键的射频存储区（各 100KB / `0x19000` 字节）：
- **`0xe7000` (`cal` / `rr`)**：**当前运行的出厂专属射频校准区**；
- **`0xce000` (`drr`)**：**默认出厂射频基表区**。

合宙官方 Luatools 在执行全量线刷底层固件时，其配置中默认包含了 `[flexfile0]`（写入 `0xe7000`）与 `[flexfile1]`（写入 `0xce000`），指向通用的未调校空模板 `MergeRfTable.bin`（MD5: `00a993cd18f39bd6cff2609ad2e69f9d`）。  
若用户在救砖或升级时执行了全片擦除（`flasherase`）或强刷，就会把每片模组出厂时在生产线上经专业射频综测仪（如安捷伦/罗德与施瓦茨）调校的参数冲刷覆盖。

在真实故障板卡（IMEI `861551056385727`）的二进制体检中证实：
1. **绝大部分被冲为公版空模板**：96KB 数据与理论未调校空模板完全一致；
2. **存在坏死扇区**：在物理地址 `0xf9000`（相对偏移 `0x12000 ~ 0x12fff` 处），整整 **4096 字节（4KB 扇区）被彻底擦成了全 `0xFF` 坏块**；
3. **搜网瘫痪根因**：该 4KB 扇区正是极其核心的 **PA 射频功率档位步进映射表（Power Step Mapping）**。缺少此表导致基带射频功放完全失控，下行频偏超差无法同步基站 PSS/SSS，表现为 USB/串口/AT 通信完全正常，但 **`AT+CSQ` 永久为 `0`、`AT+CEREG?` 永久卡在 `0, 2`（搜网拒网死锁）**。

### 2. 射频校准表的底层构成真相：为什么同型号移植能满血复活？
100KB 的校准表由两层截然不同的数据构成：
- **95% 的大头：板型与硬件拓扑定义表（同型号同批次 100% 物理通用）**：
  - 包含 PCB 走线阻抗补偿、天线匹配网络损耗、PA 功放芯片选型、全频段（B1/B3/B5/B8/B34/B38/B39/B40/B41）GPIO 开关逻辑以及被抹成全 0xFF 的 4KB 功率档位映射表；
  - 移芯官方的 `MergeRfTable.bin` 只是芯片公版粗胚，并不适配合宙板型；而从正常板卡读出的这 95% 数据，是合宙针对 Air780E 开发板硬件电路量身定制的，同型号板卡在物理上毫无二致；
- **5% 的小头：单机元器件微小公差（单板独有，但协议具备强容差自愈力）**：
  - 主要是 26MHz 温补晶振的切片微小温漂频偏（通常 < ±1 ppm）与 PA 生产微调（< 0.5dB）；
  - 4G LTE 通信协议具备极强的数字 Costas 环动态跟踪机制，基带捕捉到基站同步信号后，**10 毫秒内就会动态自适应锁死频偏**；且基站具备 TPC 闭环功率控制，会实时下调/上调模组发射功率，使单机微小公差被完全包容消化。
- **实测结论**：将同型号正常板卡的真实综测射频参数移植到故障板上，日常发短信、打电话、联网与全新出厂板卡毫无肉眼可见的区别。

### 3. 安全提取与微创手术写入规范 (SOP)
在操作底层 `FlashToolCLI.exe` 时，必须严格遵守以下工业级避坑规约：

1. **纯 ASCII 隔离沙箱（绝对避坑）**：  
   移芯 FlashToolCLI 对路径极其严苛。运行目录与 `.ini` 配置文件路径若包含中文字符，会直接触发 `string contain chinese error` 并中断。**必须将执行环境迁移至纯英文系统临时目录（如 `Temp/ec618_rf_safe_dump`）**。
2. **长度参数必须使用十六进制（绝对避坑）**：  
   `flashread` 与分卷长度必须传 `0x19000`（102,400 字节）。若写十进制 `102400`，工具会默认解析为十六进制 `0x102400`（1MB），导致 `0xe7000 + 0x102400` 溢出 `cp_flash` 最大上限（1,048,576 字节）而报 `more than 1048576 is not allowed`。
3. **保留 `[cp_system]` 使能通道**：  
   配置文件中必须声明 `[cp_system]` 并配置 `cp_sysloadskip = 1`，否则工具内部 `cpsys_support` 为 0，会拒绝读写 `cp_flash` 分区。
4. **微创分卷烧录（零全片擦除）**：  
   - 配置文件仅声明 `[flexfile0]` (`0xe7000`) 与 `[flexfile1]` (`0xce000`)；
   - 烧录命令严格执行：`FlashToolCLI.exe --cfgfile rescue_rf.ini --port COM9 burnbatch --imglist flexfile0 flexfile1`；
   - 绝不传入 bootloader、system 或 script，绝不执行 `flasherase`；
   - 烧录完毕后调用 `flashread` 回读核验 MD5（目标 MD5: `5786b980f664877c7fedca6d1c35e337`），最后发送 `sysreset` 软复位模组。

### 4. 实测战果与归档资产
- **实测战果**：故障板（IMEI `861551056385727`）在精准微创注入好板校准表后冷启动，上位机实时捕获蜂窝信号从永久 `0` 飙升至 **CSQ 22、RSRP -98 dBm**，`registration: 1` 成功驻网，瞬时识别联通 SIM 卡并读出手机号 `+8613243833879`，网络与 IP 状态全绿复活；
- **沉淀资产库**：
  - `deploy/rf_backup/good_ec618_cal_e7000.bin`：标准 100KB 出厂射频校准真机数据（MD5: `5786b980f664877c7fedca6d1c35e337`）；
  - `deploy/rf_backup/good_ec618_drr_ce000.bin`：标准 100KB 默认射频基表真机数据（MD5: `5786b980f664877c7fedca6d1c35e337`）；
  - `deploy/rf_backup/faulty_ec618_cal_e7000.bin`：故障板原始坏块（4KB 擦除全 0xFF）存档，供追溯比对。

## 八、 上位机开箱装机与在线重刷人机协同与烧录加固 (AIR-65)

### 1. 物理现实与“软件切 BootROM 盲区”破除
- **物理事实**：移芯芯片（EC718 / EC618）在正常开机运行态（COM8）下，软件向串口发送普通的 `AT+ECRST` 或 `rtos.reboot()`，硬件只执行**常规冷启动**，根本无法进入光刻 BootROM（17D1:0001 / COM9）。
- **人机协同 60 秒高频守候态**：
  - 彻底弃用“盲等 12 秒超时报错”的粗暴时序；
  - 启动烧录后进入 60 秒守候态，界面大白话提示：`👉 请在模组上【按住 BOOT 键不放，点按一下 RST 键】`；
  - 后台以 50ms 探针持续探测 USB 总线，用户触发硬件动作瞬间毫秒级捕获 COM9 并全速开刷，完成后自动发送 `sysreset` 平滑复位。

### 2. 纯英文隔离沙箱与绝对路径加固
- 原厂 `FlashToolCLI.exe` 严禁路径包含中文（报 `string contain chinese error`）；
- 上位机检测 Windows Temp 路径，若用户名含非 ASCII 则自动回退至系统盘 `C:\Temp\air780_flasher_<pid>`；
- 不仅 ini 和镜像自包含，**将 `FlashToolCLI.exe`、`soc_tools.exe` 等可执行文件一并拷贝至纯英文沙箱内部调用**，彻底杜绝源码开发环境下的中文闪退。

### 3. 上层 4 件套刚性白名单 (零出厂污染)
- 无论全新开箱装机还是已有模组在线重刷，全量烧录列表死死锁定：
  `["bootloader", "system", "cp_system", "flexfile2"]`；
- 严禁 `format_path`，严禁 `flexfile0/1`，严禁碰触出厂射频校准区与机身 NV，原本板子参数 100% 毫发无损。
